# ONE TUNNE Logistics — Master Project Specification

> **Призначення файлу.** Тут збережено повну кінцеву концепцію програми (усі функціональні й технічні вимоги всіх етапів), щоб не втрачати вимоги майбутніх етапів. Поточний етап, прогрес і наступні кроки фіксуються в [ROADMAP.md](./ROADMAP.md). Технічні рішення першого етапу та правила розробки — у [CLAUDE.md](./CLAUDE.md).

Ти — головний розробник ONE TUNNE Logistics, приватної ERP-системи з вбудованим штучним інтелектом для автоматизації міжнародної торгівлі, логістики, складського обліку, виробництва та фінансів.

Я власник проєкту, не маю професійного досвіду програмування. Можу працювати з iPhone та ПК. Якщо потрібна моя участь, надавай конкретні покрокові інструкції: що зробити, де та навіщо.

Спілкуйся українською, коротко та конкретно. Працюй максимально самостійно й економно використовуй токени.

Усі вимоги нижче описують кінцеву концепцію програми. У поточній сесії виконуй виключно перший етап, описаний у розділі 19.

## 1. Поточні дані бізнесу

- Магазин: onetunne.com
- Платформа: Shopify
- Тариф: Grow
- Carrier Calculated Shipping (CCS): активовано
- Поточний перевізник: Nova Global
- Країна відправлення: Україна
- Товари: аксесуари для електросамокатів
- Характеристики товарів, вага, габарити та митна інформація вказуються у Shopify
- Замовлення за замовчуванням пакуються в одну посилку
- Залишки товарів контролюються у Shopify
- Репозиторій GitHub: onetunne-logistics

Застосунок повинен працювати безпосередньо в адміністративній панелі Shopify та бути адаптованим під iPhone і ПК.

У майбутньому бізнес може частково або повністю переїхати до Європи. Архітектура повинна підтримувати зміну країни відправлення, складів, юридичних осіб та перевізників без переписування основної системи.

## 2. Інтеграція Shopify

- Автоматична синхронізація замовлень, товарів, варіантів, фотографій, характеристик, цін та залишків
- Автоматична обробка оплачених замовлень
- Імпорт старих замовлень
- Можливість переоформлення старих замовлень
- Фільтри, пошук та масові операції
- Редагування контактних даних і адреси
- Синхронізація статусів
- Автоматичне отримання нових замовлень через webhooks
- Передача трек-номера клієнту після фактичної передачі посилки перевізнику, а не одразу після створення накладної
- Синхронізація змін замовлень
- Обробка скасованих замовлень

Shopify залишається основним джерелом даних про товари, замовлення та доступні для продажу залишки.

Використовуй Embedded Shopify App із Custom Distribution через Shopify Dev Dashboard, актуальний офіційний Shopify App Template та App Bridge, якщо це відповідає актуальній документації.

Використовуй стабільну версію Shopify GraphQL Admin API.

Врахуй необхідні дозволи для доступу до старих замовлень, захищених даних клієнтів та fulfillment. Запитуй лише мінімально необхідні дозволи.

## 3. Міжнародна логістика

Перший перевізник — Nova Global.

### Функції

- Автоматичне створення міжнародної накладної після оплати замовлення
- Перевірка обов’язкових даних перед оформленням
- Масове створення, редагування, скасування та переоформлення накладних
- Автоматичне скасування накладної при скасуванні замовлення до відправлення, якщо це дозволено перевізником
- Оновлення накладної після зміни підтверджених даних замовлення
- Пошук раніше створених вручну накладних та прив’язування їх до Shopify
- Ручне прив’язування за трек-номером
- Захист від дублювання накладних
- Автоматичне формування інвойсів та митних документів
- Масове формування PDF
- Окремий друк накладних у форматі перевізника, інвойсів A4 та комплектувальних листів
- Змінні налаштування відправника, країни, складу та відділення
- Вибір варіантів упаковки
- Розрахунок фактичної та об’ємної ваги відповідно до правил перевізника
- Відстеження посилок
- Виявлення затримок, проблем на митниці, втрат, повернень та невдалих доставок
- Сповіщення про конкретні проблеми з відправленнями

### Статуси

Передбач окремі статуси:

1. Оплачено
2. Очікує перевірки
3. Потребує виправлення
4. Накладна створена
5. Очікує комплектації
6. Запаковано
7. Передано перевізнику
8. У дорозі
9. Митне оформлення
10. Доставлено
11. Проблема з доставкою
12. Повернення
13. Скасовано

### Обмеження та правила

- Не позначай замовлення відправленим лише через створення накладної.
- Зберігай відповідність між ID замовлення Shopify, внутрішнім ID відправлення та номером накладної перевізника.
- Перед повторним створенням накладної після помилки API перевіряй, чи вона вже не була створена перевізником. Якщо результат невідомий і його неможливо перевірити, передавай ситуацію на ручний розгляд.
- Не створюй дублікати при повторних запитах, збоях сервера або інтернету.
- Не допускай конфліктів із чинним застосунком доставки.
- Не припускай наявності непідтверджених методів API. Точний API Nova Global та права доступу визначимо після отримання документації й ключів.
- Не використовуй внутрішній український API як заміну міжнародному без підтвердження сумісності.

## 4. Автоматичний розрахунок доставки в Shopify Checkout

Використовуй можливості Shopify CarrierService API відповідно до актуальної документації.

- Розрахунок вартості доставки до оплати замовлення
- Урахування країни, адреси, товарів, кількості, ваги, габаритів та упаковки
- Підтримка договірних тарифів перевізника
- Можливість встановлювати фіксовану або відсоткову націнку
- Окремі налаштування націнки для різних країн
- Приховування недоступних способів доставки до конкретних країн
- Можливість вибору перевізника клієнтом у майбутньому
- Без безкоштовної доставки за замовчуванням
- Порівняння суми доставки, сплаченої клієнтом, із фактичною вартістю
- Регульований допустимий поріг різниці у валюті або відсотках
- Сповіщення та призупинення оформлення при перевищенні порога
- Резервний сценарій на випадок недоступності API перевізника
- Регульовані правила упаковки та пріоритети їх вибору
- Кешування тарифів із контрольованим терміном актуальності

### Мито

Мито не включається до вартості доставки. Платник мита визначається правилами країни, умовами перевізника та можливостями компанії.

Компанія сплачує мито там, де це можливо та передбачено налаштуваннями. В інших випадках його сплачує клієнт. Необхідно коректно інформувати клієнтів про можливі додаткові платежі.

### Обмеження та правила

- Враховуй обмеження часу відповіді Shopify та вимоги до надійності розрахунку тарифів.
- Не допускай, щоб резервні тарифи випадково дозволяли доставку до заборонених країн.
- Не використовуй мовну модель для розрахунку тарифів у Checkout. Розрахунок повинен бути швидким, детермінованим та надійним.
- Не відключай поточний застосунок доставки до повного тестування нового та мого підтвердження.

## 5. Перевірка та виправлення даних

- Перевірка міжнародних телефонів
- Автоматичне виправлення однозначних помилок формату телефону
- Перевірка міжнародних телефонних префіксів
- Пошук відсутнього поштового індексу через перевірені адресні довідники
- Перевірка адреси, країни, міста та поштового індексу
- Окремі правила для країн, де поштові індекси не використовуються
- Перевірка необхідних характеристик товарів
- Перевірка митної інформації
- Аналіз помилок, отриманих від API перевізника

### Правила

- Автоматично виправляй лише однозначні та підтверджені помилки.
- Не вигадуй цифри телефону, адреси, поштові індекси, митні коди, вартість товарів або інші дані.
- Якщо є декілька можливих варіантів виправлення, потрібне підтвердження менеджера.
- Усі неоднозначні ситуації передавай до розділу «Проблеми» з поясненням причини та запропонованим рішенням.
- Передбач ручне виправлення даних із подальшим оновленням Shopify та накладної, якщо це дозволено API.
- Зберігай початкові та виправлені дані, причину зміни та історію операцій.

- Перемикання між EUR, USD та UAH
- Збереження початкової валюти та курсу конвертації
- Експорт в Excel
- Формування звітів для бухгалтерії
- Ручне внесення та коригування витрат

### Правила

- Зберігай історичні ціни, собівартість та курси валют, щоб зміни поточних цін не впливали на попередні фінансові звіти.
- Використовуй точні десяткові типи даних для фінансових розрахунків.
- У майбутньому передбач можливість додавання комісій платіжних систем, реклами, зарплат, податків та інших витрат.
- Не називай показник чистим прибутком, якщо враховані не всі витрати та податки.
- Не здійснюй автоматичні повернення коштів без підтвердження власника.

## 10. Вбудований ШІ-асистент

Асистент повинен мати можливість отримувати інформацію та виконувати дозволені операції через чат.

### Приклади команд

- Зміни адресу в замовленні №1850
- Зміни номер телефону клієнта
- Переоформи накладну
- Покажи всі замовлення без накладних
- Покажи посилки, затримані на митниці
- Призупини відправлення до конкретної країни
- Зміни націнку на доставку
- Покажи прибуток за місяць
- Покажи товари, які закінчуються
- Створи звіт про проблемні відправлення
- Збережи мою вказівку як постійне правило

ШІ повинен працювати через обмежений набір серверних інструментів із перевіркою дозволів, а не мати необмежений доступ до бази даних або сервера.

### Режими

Передбач три режими:

- **Ручний** — усі зовнішні дії підтверджує менеджер
- **Напівавтоматичний** — система виконує дозволені стандартні операції, складні зміни підтверджує менеджер
- **Автоматичний** — система самостійно виконує дозволені та перевірені операції

### Додаткові вимоги

- Підтвердження критичних і фінансових операцій
- Попередній перегляд наслідків масових змін
- Місячний бюджет на використання ШІ
- Статистика витрат
- Обмеження запитів
- Захист від шкідливих інструкцій у даних клієнтів
- Глобальна кнопка призупинення автоматизації
- Призупинення автоматизації окремого замовлення
- Можливість зберігати підтверджені власником правила
- Дотримання прав доступу користувача, який звертається до ШІ

Працівник не повинен отримувати доступ до фінансової інформації навіть через ШІ-асистента.

Використовуй звичайний програмний код для стандартних операцій. Використовуй мовну модель лише там, де вона справді необхідна.

Передбач можливість заміни моделі ШІ в налаштуваннях у майбутньому без переписування всієї програми.

## 11. Центр розвитку програми

Це один із ключових модулів.

Система повинна:

- Реєструвати технічні помилки та помилки оформлення накладних
- Групувати повторювані проблеми
- Визначати можливі причини
- Пропонувати нові правила автоматизації
- Формувати готові технічні завдання для Claude Code
- Дозволяти власнику підтверджувати підтримувані нові правила без програмування
- Зберігати історію правил і можливість їх скасування
- Перевіряти нові правила на тестових даних
- Показувати ефективність автоматизації
- Зберігати історію оновлень та запланованих функцій
- Повідомляти про недоступність зовнішніх API
- Повідомляти про збої фонових процесів
- Показувати кількість проблем, вирішених автоматично

Приклад: система виявила повторювану помилку формату телефонів певної країни, запропонувала перевірене правило, власник затвердив його, система застосовує правило надалі.

### Правила

- Нові правила повинні мати обмежені параметри, перевірку коректності, тестування, історію версій та можливість відкату.
- Якщо проблема потребує зміни програмного коду, формуй готовий промт для Claude Code з описом проблеми, умовами її виникнення, очікуваною поведінкою та критеріями перевірки.
- Не включай реальні персональні дані клієнтів у такі промти.
