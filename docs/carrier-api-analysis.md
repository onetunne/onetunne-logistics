# Етап 3: аналіз API перевізника (перевірено 2026-11-26 за офіційною документацією)

## Два різні API групи «Нова пошта»
| | **Nova Global Partners API** | **Nova Post API v1.0** |
|---|---|---|
| Документація | https://nova.global/partners_api/ (v2.8, 30.04.2026) | https://api-portal.novapost.com |
| Доступ | лише після договору співпраці з Nova Global | API-ключ бізнес-кабінету |
| Авторизація | HTTP Basic `login:password` + `company_id` | API-ключ → `GET /clients/authorization` → JWT (~1 год) |
| Тестове середовище | так, окремі логін/пароль (`test-api.novaposhta.international:8243`) | пісочниця `api-stage.novapost.com`, **але ключі для клієнтів з України там не видаються** |
| Міжнародні з України | так (IEW) | так — розділ «Cross-border shipments from Ukraine», ендпоінт для клієнтів з України `https://api.novaposhta.ua/v.1.0` |
| Створення / скасування | `IEW/create` 2.0 (повтор `api_order` → 422 COR7), `IEW/cancel` 2.0 | `POST /shipments`, скасування, редагування |
| Друк | `IEW/print` (PDF base64) | `GET /shipments/print` (етикетки, інвойс) |
| Відстеження | `IEW/getTrackingHistory` (за номером / api_order) | `GET /shipments/tracking`, `/tracking/history` |
| Розрахунок вартості | у поточній версії **немає** | `POST /shipments/calculations` (вартість, строк, мито) |

## Сумісність ключа `NOVA_POSHTA_API_KEY`
- З **Nova Global Partners API** — **не сумісний** (там логін/пароль і company_id за договором).
- З **Nova Post API v1.0** — сумісний, **якщо** ключ створено в бізнес-кабінеті new.novaposhta.ua
  (Налаштування → Безпека). Ключ старого API `api.novaposhta.ua/v2.0/json` — інший механізм.
- Точно перевірити можна лише запитом. Тестовий сервер Render під час запуску сам робить перевірку
  **без створення відправлень**: отримання JWT + розрахунок вартості зразкової посилки UA → DE.
  Результат — рядок `nova_post.key_check` у журналі Render (ключ і токен не записуються).

## Рішення, потрібне від власника
1. Через який договір працюємо: **Nova Global** (потрібні логін/пароль/company_id і тестові облікові дані) чи
   **Nova Post API v1.0** з наявним ключем (міжнародні з України)?
2. Для Nova Post API тестового середовища для українських ключів немає — перевірка створення накладної можлива лише
   на робочому API (реальна накладна, яку потім скасовують) — лише з вашого окремого дозволу.

## Що реалізовано на етапі 3 (без створення накладних)
- Клієнт Nova Post API v1.0: JWT з кешем і повторним отриманням при 401, класифікація помилок, маскування ключа/JWT.
- Розрахунок вартості (`/shipments/calculations`) з одиницями з документації (грами з точністю 10 г, міліметри).
- Автоматична перевірка ключа під час запуску сервера (лише читання).
- Заглушка Nova Global оновлена перевіреними фактами; без облікових даних — вимкнена.
